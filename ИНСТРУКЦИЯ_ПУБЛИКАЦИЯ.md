# Как открыть проект коллеге по защищённой ссылке

Подготовленная копия предназначена для **учебной демонстрации на синтетических данных**, не для банковского продакшена.

## Что подготовлено

- Исходный интерфейс и модель сохранены.
- На облаке приложение слушает порт, предоставленный хостингом.
- В облачном режиме (`DEPLOY_MODE=1`) приложение **не запустится без пароля** длиной минимум 12 символов.
- Вход защищён HTTP Basic Auth (браузер попросит логин и пароль). На публичном хостинге используйте только HTTPS.
- Пароль задаётся в настройках хостинга, **не хранится в исходном коде**.

## Публикация через Render + GitHub

1. Создайте **приватный** репозиторий GitHub и загрузите туда файлы из папки `prime_elite_prototype` (именно содержимое папки, чтобы `render.yaml` был в корне репозитория). Не загружайте реальные клиентские данные или секреты.
2. В Render выберите **New → Blueprint**, подключите GitHub и выберите репозиторий с `render.yaml`.
3. При настройке укажите секрет `APP_PASSWORD` (сложный пароль не короче 12 символов). `APP_USERNAME` по умолчанию `demo`; его можно поменять в Environment.
4. Запустите Deploy. После успешного запуска Render покажет адрес вида `https://...onrender.com`.
5. Откройте ссылку в режиме инкогнито, проверьте, что сайт **не открывается без логина и пароля**, а после ввода данных работает.
6. Передайте коллеге ссылку и учётные данные **разными каналами**. Не публикуйте их в общем чате.

Если Blueprint не позволяет указать секрет при создании, добавьте `APP_PASSWORD` в разделе Environment **до первого успешного запуска** и выполните redeploy.

## Важно про сохранение назначений

В этом учебном проекте назначения сохраняются в `data/live_assignments.json`. На бесплатном Render локальная файловая система **не является постоянным хранилищем**: после пересоздания инстанса или нового деплоя назначения могут исчезнуть. Для устойчивого хранения нужна внешняя БД (например PostgreSQL) и изменение серверной логики. Два одновременных облачных инстанса также не должны использовать этот JSON как общую БД.

## Ограничения безопасности

- HTTP Basic Auth с одним общим паролем — подход для краткой учебной демонстрации, **не** для чувствительных данных или промышленного использования.
- Все, кому известны учётные данные, могут менять назначения и нажать «Сбросить».
- Для индивидуального отзыва доступа нужны отдельные учётные записи или внешний identity-провайдер.
- Бесплатный тариф Render может засыпать; первый запрос после простоя может выполняться дольше.
- Проверьте условия и лимиты тарифа Render на момент публикации.

## Локальный запуск

`Запустить на Mac.command` продолжает запускать приложение локально без пароля. Облачный режим включается **только** переменной `DEPLOY_MODE=1`.
